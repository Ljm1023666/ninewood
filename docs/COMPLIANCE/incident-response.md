# 数据安全事件应急预案

依据：《个人信息保护法》§57、《网络安全法》§42-§43

> 内测版 v0.1 — 公测前需法务审阅 + 桌面演练 + 法人签字

## 一、适用范围

本预案适用于九木（Ninewood）平台发生或可能发生的数据安全事件，包括但不限于：

1. 用户个人信息泄露、篡改、丢失
2. 系统被入侵 / 数据库被拖库
3. AI 输出违规内容且未及时处置
4. 内部人员违规访问 / 滥用数据
5. 第三方服务（SMS / LLM / Sentry）发生安全事故

## 二、事件分级

| 级别 | 名称 | 标准 | 响应时间 |
|---|---|---|---|
| **P0** | 特别重大 | ≥ 100 万人敏感信息泄露；或核心系统被控 | 立即（≤ 1h 报告网信办） |
| **P1** | 重大 | 1 万-100 万人信息泄露；或关键功能失效 | 2h 内启动响应 |
| **P2** | 较大 | < 1 万人信息泄露；或局部功能异常 | 24h 内启动响应 |
| **P3** | 一般 | 单点异常，无数据泄露 | 72h 内处置 |

> 内测期用户数 < 200，绝大多数事件按 P2/P3 处理；但任何**未成年人信息泄露**自动升 P1。

## 四、响应流程

### 4.1 发现（0-15min）

1. 谁发现 → 立即报告应急小组（微信群 + 电话）
2. 应急小组 15min 内判断事件级别
3. P0/P1 立即启动响应；P2/P3 视情况启动

### 4.2 止损（15min-2h）

1. 切断攻击源（封 IP / 撤权限 / 停服务）
2. 隔离受影响系统（防止横向扩散）
3. 保留现场证据（磁盘镜像、日志、内存快照）

### 4.3 排查（2h-24h）

1. 追溯攻击路径
2. 评估影响范围（受影响用户数 / 数据种类）
3. 编写事件报告（详见 §5）

### 4.4 报告（按级别）

| 级别 | 报告对象 | 时限 |
|---|---|---|
| P0 | 网信办 + 公安网安 + 工信部 | 1h |
| P1 | 网信办 + 公安网安 | 24h |
| P2 | 内部 + 留存报告 | 7 天 |
| P3 | 内部周报 | 月度 |

> **报告渠道**：
> - 国家网信办举报：https://www.12377.cn 或当地网信办
> - 公安网安：110 / 当地网安大队
> - 工信部：12300

### 4.5 通知用户（P0/P1 必做）

1. 通过站内消息 / 短信 / 邮件通知受影响用户
2. 内容：事件概要 + 受影响数据类型 + 已采取措施 + 用户建议
3. 模板见 [user-notification-template.md](user-notification-template.md)（内测期暂不建）

### 4.6 整改（7-30 天）

1. 复盘事件根因
2. 制定技术 + 流程整改方案
3. 落地修复 + 回归测试
4. 写复盘报告
