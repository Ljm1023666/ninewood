## 修复 /loops 纵向占比条：竖立 + 不随容器移位

- 根因：占比 slider 嵌在被缩放的 pane header 内，拖动一个分区时其它分区的 header 被整体推挤，导致 slider 位置跟着移动。
- 修复：`MyLoopsPage.tsx` 将占比控制抽离为独立的「比例轨」`my-loops-ratio-rail`（不参与 pane 缩放的 flex 分配，缩放分区时轨道固定不动）。
  - 新增 `boardLayout`（single/horizontal/vertical）派生变量，board 始终 flex：horizontal=轨在上方+panes 横排；vertical=轨在左侧+panes 竖排。
  - panes 容器 `.my-loops-panes` 用 `flexGrow: ratios[kind]; flexBasis: 0` 等比分配空间（gap 由 flex 自动扣除，避免溢出）。
  - 纵向 slider 用 `writing-mode: vertical-lr; direction: rtl`（兼容 `-webkit-appearance: slider-vertical`）实现竖立，max 在顶部。
  - 移除原 `.my-loops-pane__ratio` 内嵌滑块。

## /loops 比例与总尺寸工具改造

- 新增「总尺寸」独立工具（与分区占比解耦）：`totalSize` 状态（默认 100，范围 60-120），同步 URL `total`，可刷新/分享还原。
  - 纵向：panes 整体高度 = `620 * total/100` px；横向：panes 整体宽度 = `total%`。
  - 工具栏新增 `my-loops-total-size` 滑块（纵向显示「总高度」、横向显示「总宽度」）。
- `updateRatio` 改为**相邻交换**逻辑：拖动某滑块只与它直接相邻的 pane 交换空间；拖两端仅影响唯一相邻 pane，拖中间同时影响左右两个相邻 pane；保持总和恒为 100%、每块 ≥20%。内部用小数计算避免舍入破坏总和，显示值取整。
- 铺满：pane 的 `flex-basis` 改为 `calc((100% - (n-1)*16px) * ratio / 100)`，三块 + gap 恰好等于 panes 容器 100%，默认铺满页面。
- CSS：`.my-loops-panes` 改 `flex:0 0 auto`，横向加 `align-self:flex-start + margin-inline:auto`（宽度<100%时居中），移除纵向固定 height（改由内联控制），新增 `.my-loops-total-size` 样式。
